## What was checked and found sound

- XSS: every student-derived value goes through `textContent` (`cell()` 99-106, `confirmText` 245, `showMessage` 75) or `.value` (174-176). `formTitle` uses only the numeric id. `dataset.id` and `dataset.label` are set through properties. No HTML-string sink exists in `app.js`.
- CSP compatibility: the HTML has one external script and one external stylesheet, with no `style=`, `on*=`, `<style>` or inline `<script>`. `app.js` does not set `style` attributes or use `eval`/`Function`/string `setTimeout`. `hidden` and `className` toggling is CSP-safe. The CSS `[hidden]{display:none !important}` keeps `hidden` effective on flex or grid elements.
- Path traversal and allow-list: `assets.get(path)` is an exact-key lookup in a `Map` built from a constant list. Request paths never reach the filesystem. Files are read once at startup, so there is no per-request I/O or TOCTOU. Percent-encoded, trailing-slash, case-varied and absolute-form URLs miss the map and fall through to `ROUTE_NOT_FOUND`. The query string is stripped identically for both routing paths. A missing `public/` file fails at startup through the existing `Startup failed:` handler.
- HEAD/405: HEAD returns 200 with the correct `Content-Length` and no body. Other methods throw `MethodNotAllowedError`, which the shared handler turns into the standard JSON 405 and logs.
- Persistence/validation/errors: untouched, and still covered by the earlier tests. No CORS header is added (asserted at `tests/frontend.test.js:71`).
- Error paths in the UI: 422 (field errors plus banner), 409 (email field plus banner), 404 on edit (reset, banner, reload), 404 on delete (banner, reload), network (readable message through `NETWORK_ERROR`), and other statuses (API message or `Request failed (n)`).
- Dialog: native `<dialog>` with `aria-labelledby`, Cancel is the first focusable button (a safe default for a destructive action), Esc leaves `returnValue === ''` so nothing is deleted, and `returnValue` is reset before each `showModal()`.
- Responsive CSS: a single-column layout at <=900px, stacked cards at <=640px, `min-width:0` on the grid child, and a scroll wrapper on the table. The viewport meta tag is present. All form controls have labels (`for`/`id`), and the search label is visually hidden.
- Dead code: none found. Every function in `app.js` is used. The `module.exports` guard is needed for the client tests.

## Overall verdict

Approve with changes. No critical findings and nothing blocks verification. The backend change is minimal, safe, and leaves `/students` behavior unchanged. I recommend fixing F-1 (automated coverage of the UI logic, or a committed browser script) before the verification phase, and the cheap code fixes F-2, F-3/F-4 (one `busy` guard), F-5 and F-6 while in the file. F-7 to F-11 can be fixed in the same pass or accepted with a note.

Not verified by this review: rendering in a real browser (layout at 640/900px, focus behavior, dialog, CSP enforcement). These belong in the verification phase.
